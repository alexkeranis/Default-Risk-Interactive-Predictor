03 · Method

How it was built

Protocol

  • Stratified 80/20 development/test split. The test set is scored exactly once.
  • One scikit-learn pipeline (imputation → domain features → encoding → model → calibration) is fit inside every fold. The same serialized object serves single and batch inference.
  • Equal tuning budget per model family, inner 5-fold CV, scored by log loss (a proper scoring rule).
  • Repeated stratified 5×3 CV with the Nadeau–Bengio corrected t-test. A pre-registered 1-SE rule prefers the simpler model.
  • Post-hoc calibration chosen on out-of-fold Brier score. Cutoffs are chosen on out-of-fold predictions.

Full benchmark report · Source code

In-browser model

The training pipeline exports fitted coefficients, tree structures, imputation medians and calibration maps to JSON. assets/model.js re-implements only the arithmetic, and CI checks it against the fitted Python pipelines: logistic regression to 1e-9, XGBoost to 1e-5. Drivers are exact for logistic regression and Saabas path attributions for XGBoost, in log-odds space.

Limitations

  • Synthetic labels follow a near-deterministic rule, so scores here overstate what real bureau data allows.
  • Tiers are not defaults: every dollar figure depends on the assumed PD per tier.
  • No time dimension, so no out-of-time validation or drift monitoring.
  • Age and employment status are sensitive attributes in many jurisdictions and would need fairness review before real use.
